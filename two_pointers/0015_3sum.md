# 15 — 3Sum

## Problem

All unique triplets summing to 0.

**Example:** `nums = [-1,0,1,2,-1,-4]` → `[[-1,-1,2],[-1,0,1]]`

## Walkthrough

Sort, then for each anchor `i`, two-pointer sweep (problem 167's mechanics) over the range right of it: sum < 0 → L++, sum > 0 → R−−, hit → collect and skip duplicate values on both sides. A repeated anchor value is skipped entirely — its sweep would only regenerate old results.

**[1] sorted [−4,−1,−1,0,1,2] — anchor i=0 (−4)**
```text
[-4, -1, -1, 0, 1, 2]
  i   L           R
-4−1+2=−3 <0 → L++ … every pair with −4 sums negative: anchor dies, no hit
```

**[2] anchor i=1 (−1) — L starts on the duplicate −1**
```text
[-4, -1, -1, 0, 1, 2]
      i   L       R
−1−1+2 = 0 ✓ collect [-1,-1,2] → skip dups: L moves to 0
```

**[3] same anchor — second hit**
```text
[-4, -1, -1, 0, 1, 2]
      i       L   R
−1+0+2 = 1 > 0 → R−− … L=4? recount: L=3(0),R=5: 1>0 → R=4(1): −1+0+1=0 ✓
collect [-1,0,1] → L=4, R=3: crossed, anchor done
```

**[4] anchors −1 (dup: skipped), 0, 1 — nothing**
```text
[-4, -1, -1, 0, 1, 2]
             i  L  R
0+1+2=3 > 0 → R−− → L=R: done
```

**[5] result**
```text
[[-1,-1,2],[-1,0,1]] ✓
```

Why it works: sorted order makes each two-pointer repair exhaustive for its anchor (too small ⇒ only L++ helps; too big ⇒ only R−−), and value-skipping — at anchors and after hits — guarantees uniqueness without deduplicating output. O(n²) after an O(n log n) sort; the middle sibling of 167 (two pointers) and 18 (4Sum, `arrays_and_hashing/`).
