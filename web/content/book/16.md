Greedy: make the locally best choice and never revisit it. When it works it beats DP by a dimension — O(n lg n) instead of O(n²) or O(n³) — but it works only when a proof says it does. The chapter's method: start from the DP, then show one choice is always safe, collapsing the table into a scan.

## 16.1 Activity selection

Pick the most mutually compatible activities from `[s_i, f_i)` intervals. The DP is obvious (optimal substructure over `S_ij` sets between activities) — and unnecessary.

The greedy: **always take the activity that finishes first**, then recurse on what's left that starts after it. Proof sketch: some optimal solution includes the earliest-finishing activity a₁ (exchange argument — swap whatever starts the optimal set for a₁; finishing earlier can only leave more room). After the greedy choice, the remainder is a smaller instance — no table, one pass after sorting by finish time. O(n lg n) dominated by the sort.

## 16.2 The two ingredients

1. **Greedy-choice property** — a locally optimal choice can be extended to a globally optimal solution. This is *stronger* than optimal substructure: DP asks "which choice is best?" after solving subproblems; greedy commits to the choice *before* looking at subproblems. It's what lets you drop the max() over choices.
2. **Optimal substructure** — shared with DP, proven the same cut-and-paste way.

The development recipe (worth internalizing): find the DP → identify a choice that's always safe → prove it with an exchange argument → delete the table. "Beneath every greedy algorithm there is almost always a more cumbersome dynamic-programming solution."

**The cautionary pair — knapsack:** 0-1 knapsack (take the item or don't) requires DP; fractional knapsack (take gold dust by weight) is greedy by value-density. Nearly identical problems, different complexity classes of solution. If a greedy feels right but you can't prove it, the 0-1 knapsack counterexample is the first thing to try.

Greedy in the wild requires the right sort/preprocessing: activities by finish time, Kruskal by edge weight, Dijkstra by distance (a priority queue, Ch. 6 returning). "Sort, then scan" *is* the greedy pattern in `greedy/`.

## 16.3 Huffman codes

Prefix-free variable-length codes: frequent characters get short codewords. Prefix-free ⟺ the code is a binary tree with characters at leaves. Building the optimal tree is greedy: repeatedly merge the two lowest-frequency nodes (a min-heap — Chapter 6 again); the merge order determines the code. n−1 merges, O(n lg n).

Correctness is the greedy-choice theorem again: the two least frequent characters sit as deepest siblings in *some* optimal tree (exchange argument), so committing to that merge is safe.
