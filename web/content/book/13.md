Red-black trees fix Chapter 12's cliff: a plain BST can degrade to a chain, so O(h) becomes O(n). A red-black tree *guarantees* h = O(lg n) worst case, keeping every dynamic-set operation logarithmic. This is the `std::map` / Java `TreeMap` implementation.

## 13.1 The properties

A BST where each node carries one color bit, satisfying:

1. every node is red or black
2. the root is black
3. red nodes have black children (no two reds in a row)
4. every root-to-NIL path has the same number of black nodes (the **black-height**)

The payoff: the longest path is at most twice the shortest — a path can alternate red/black at best, so h ≤ 2·lg(n+1). One sentinel `T.nil` (always black) replaces all NILs, so boundary nodes have parents and the fixup code needs no special cases.

## 13.2 Rotations

The local surgical move that changes height without breaking the search property: LEFT-ROTATE(x) lifts x's right child y above x, y's left subtree crosses over to x. Three subtrees α, β, γ keep their relative order, so the BST property survives. O(1), constant pointers. Rotations are the only structural change the tree ever needs — everything else is recoloring.

## 13.3 Insertion

Plain BST-insert, color the new node **red** (red can't break property 4, only possibly 3), then RB-INSERT-FIXUP repairs upward. The fixup is a loop of at most O(lg n) cases, driven by "what does my uncle look like":

- red uncle → recolor parent and uncle black, grandparent red, continue upward (property 4 kept, pushes the redness up two levels)
- black uncle → one or two rotations plus recoloring, terminate

Total: ≤ 2 rotations, O(lg n) recolors.

## 13.4 Deletion

RB-DELETE wraps Chapter 12's cases via RB-TRANSPLANT, tracking whether removing/splicing a *black* node has depleted some path's black count (property 4 at risk). The fixup restores it with rotations and recolorings — the famous fiddly part; the book itself apologizes with four cases mirrored into eight. The engineering takeaway is the design, not memorized cases: black-height is an invariant you can push sideways (a rotation) or up (recolor), and the fixup walks until it can discharge the debt.

## Why care, practically

You will likely never write one from scratch. What transfers:

- the *idea* of maintaining balance with local repairs — it returns in B-trees (disk-friendly, Ch. 18), treaps, AVL, and skip lists
- amortized/spread-out restructuring — insert cheap, pay maintenance in O(1)-size moves
- sentinel nodes to kill boundary cases

`sortedcontainers.SortedList` (the competitive-programming default) is skip-list-flavored for the same reason: guaranteed-log ordered dictionary with cheap updates. When an interview needs "ordered + dynamic," that's this chapter's slot.
