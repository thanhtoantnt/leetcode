B-trees are red-black trees tuned for disks. Same O(lg n) guarantee, but the constant is what's being bought: each node visit is a disk access costing milliseconds, so make nodes huge and the tree short.

## Why disks change the design

RAM access ~50ns; a disk rotation ~8ms — five orders of magnitude. Data moves in **pages** (blocks), so the cost model counts page reads/writes, not instructions. A structure that touches few pages wins even if it does more CPU work per page. Height = page accesses = the resource to minimize.

## 18.1 The structure

A B-tree of minimum degree t ≥ 2:

- every node holds between t−1 and 2t−1 keys in sorted order (the root is exempt from the minimum)
- an internal node with n keys has n+1 children, keys acting as range separators (search-tree property, generalized)
- **all leaves at the same depth**

Height bound: since nodes are at least half full, n keys force height h ≤ log_t((n+1)/2). With branching factor in the hundreds, a billion keys fit in 3–4 pages — versus ~30 nodes for a binary tree. The log's *base* is the entire point: B-tree height is lg n / lg t.

## 18.2 Operations — split before descending

Search is a multi-way descend, O(t) scan per node, O(h) pages.

Insert keeps the no-backtracking discipline: **split any full child before descending into it**. A split pushes the child's median key up to the parent; splitting the root grows the tree by one level (the only way height increases — at the top, keeping leaves level). So an insertion that reaches a leaf always finds room there. Deletion is the mirror image and the fiddly one: descend only into nodes that have ≥ t keys, borrowing a key from a sibling (rotation) or merging two siblings when both are minimal — the pre-emptive "make sure there's slack below" move, the same spirit as B-TREE-INSERT's pre-splitting.

## 18.3 in one line

Full nodes split, empty-ish nodes merge/steal, tree only grows at the root — invariants maintained top-down in one pass each way.

Databases (MySQL InnoDB, Postgres), file systems (ext4, NTFS, Btrfs) all speak B+tree variants: keys only in leaves, internal nodes pure index, leaves linked for range scans — the augmented version of this chapter (à la Ch. 14).
