Chapter 3 is the grammar lesson: the notation every later chapter is written in. Θ, O, Ω bound functions to within constant factors once n is large enough — the lower-order terms and leading constants that Chapter 2 computed exactly are thrown away on purpose.

## The three notations

For asymptotically positive `f` and `g`:

| Notation | Meaning | Picture |
|---|---|---|
| `f = Θ(g)` | sandwiched: `c₁g ≤ f ≤ c₂g` for n ≥ n₀ | between two scaled copies of g |
| `f = O(g)` | upper bound only: `f ≤ cg` for n ≥ n₀ | at or below one scaled copy |
| `f = Ω(g)` | lower bound only: `f ≥ cg` for n ≥ n₀ | at or above one scaled copy |

Θ = O ∩ Ω. The book's worked example: prove `½n² − 3n = Θ(n²)` by exhibiting constants — divide through by n², pick `c₁ = 1/14`, `c₂ = 1/2`, `n₀ = 7`. Any valid choice suffices. The non-example: `6n³ ≠ Θ(n²)`, because `6n³ ≤ c₂n²` forces `n ≤ c₂/6`, impossible for all large n.

Two notations for non-tight bounds:

- `f = o(g)` — little-oh: upper bound that is *not* tight. Equivalent to lim f/g = 0. So `2n = o(n²)` but `2n² ≠ o(n²)`.
- `f = ω(g)` — little-omega: non-tight lower bound; lim f/g = ∞.

## Which running time do you mean

Insertion sort makes this precise:

- worst case is Θ(n²) — and this *implies* O(n²) on **every** input
- best case is Θ(n) (sorted input)
- so the unqualified "running time" is both Ω(n) and O(n²) — and neither bound is tight for all inputs

The blanket statement lives at the worst case; Ω of the unqualified time is really a statement about the best case. Chapter 2's sloppy phrasing gets cleaned up here.

## Notation inside equations

`2n² + 3n + 1 = 2n² + Θ(n)` — the Θ(n) is an *anonymous function* standing for "something in Θ(n)". On the right of an equals sign, asymptotic notation absorbs detail; chains like `2n² + 3n + 1 = 2n² + Θ(n) = Θ(n²)` are read one link at a time. `O(1)` means some constant.

## Common functions to know cold

Monotonicity, floors/ceilings (`⌊n/2⌋ + ⌈n/2⌉ = n`), modular arithmetic, polynomials vs exponentials (any `n^a` is `o(b^n)` for b > 1 — the sort-vs-search wall), logarithms in any base differ by a constant factor, factorials, the iterated logarithm lg* n, Fibonacci.

One habit worth stealing: when comparing two algorithm candidates, you are asking a question about *functions* (`is f = o(g)?`), and the limit test is usually the fastest tool.
