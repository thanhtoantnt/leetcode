Chapter 3 is the grammar lesson: the notation every later chapter is written in. Θ, O, Ω bound functions to within constant factors once n is large enough — the lower-order terms and leading constants that Chapter 2 computed exactly are thrown away on purpose.

## The three notations

For asymptotically positive `f` and `g`:

| Notation | Meaning | Picture |
|---|---|---|
| `f = Θ(g)` | sandwiched: `c₁g ≤ f ≤ c₂g` for n ≥ n₀ | between two scaled copies of g |
| `f = O(g)` | upper bound only: `f ≤ cg` for n ≥ n₀ | at or below one scaled copy |
| `f = Ω(g)` | lower bound only: `f ≥ cg` for n ≥ n₀ | at or above one scaled copy |

Θ = O ∩ Ω. A proof of Θ is just *exhibiting the constants* — the book's worked example, `½n² − 3n = Θ(n²)`, done honestly:

```text
Upper:   ½n² − 3n  ≤  ½n²              for all n ≥ 0     (drop −3n)
Lower:   ½n² − 3n  ≥  ⅟₁₄n²   ⟺  (3/7)n ≥ 3   ⟺   n ≥ 7

so c₁ = 1/14, c₂ = 1/2, n₀ = 7.       ∎

Check at the boundary n = 7:  ½·49 − 21 = 3.5  and  49/14 = 3.5 — tight.
Check at n = 100: 4700 vs [350, 5000] — comfortably sandwiched.
```

Any valid constants suffice; nobody grades your c₁. The non-example: `6n³ ≠ Θ(n²)`, because `6n³ ≤ c₂n²` forces `n ≤ c₂/6` — no constant beats a growing ratio.

Two notations for non-tight bounds:

- `f = o(g)` — little-oh: upper bound that is *not* tight. Equivalent to lim f/g = 0. So `2n = o(n²)` but `2n² ≠ o(n²)`.
- `f = ω(g)` — little-omega: non-tight lower bound; lim f/g = ∞.

## Which running time do you mean

Insertion sort makes this precise:

- worst case is Θ(n²) — and this *implies* O(n²) on **every** input
- best case is Θ(n) (sorted input)
- so the unqualified "running time" is both Ω(n) and O(n²) — and neither bound is tight for all inputs

The blanket statement lives at the worst case; Ω of the unqualified time is really a statement about the best case. Chapter 2's sloppy phrasing gets cleaned up here.

## Notation inside equations

`2n² + 3n + 1 = 2n² + Θ(n)` — the Θ(n) is an *anonymous function* standing for "something in Θ(n)". On the right of an equals sign, asymptotic notation absorbs detail; chains like `2n² + 3n + 1 = 2n² + Θ(n) = Θ(n²)` are read one link at a time. `O(1)` means some constant.

## The limit test — the fastest tool in the chapter

To compare two candidates, divide and take the limit:

```text
lim (3n² + 5n) / (n²)      = 3      →  Θ, with the constant visible
lim (2n) / (n²)            = 0      →  2n = o(n²)   (strictly smaller)
lim (n lg n) / n           = ∞      →  n lg n = ω(n)
lim (lg n) / n             = 0      →  even logs lose to linears
lim (n^100) / (1.01ⁿ)      = 0      →  every polynomial is o(exponential)
```

That last one is the sort-vs-search wall of Chapter 1 and the P-vs-NP wall of Chapter 34 in one line: constants and powers eventually lose to exponentials, always.

## Crossovers you should feel

Asymptotics ignore constants — but constants decide *when* the asymptotic winner actually wins:

| Race | Crossover | Meaning |
|---|---|---|
| 100n vs 3n² | n = 34 | the linear algorithm with 33× the constant wins only up to 34 elements |
| n² vs 2ⁿ | n = 4 (16=16), then 2ⁿ runs away | exponentials eat quadratics almost immediately |
| lg n vs √n | touching at n = 16 (4 vs 4) | logs are slower than square roots forever after |
| ½n² vs 100 n lg n | n ≈ 1500 | the practical "should I rewrite it?" threshold |

Rule of thumb: below the crossover, the *simpler* algorithm wins; above it, the asymptotically better one. Insertion sort inside merge sort's base case (Exercise 2.1-... the hybrid trick, what Timsort does) is exactly this table exploited.

## Common functions to know cold

Monotonicity, floors/ceilings (`⌊n/2⌋ + ⌈n/2⌉ = n` — how MERGE-SORT splits odd n), modular arithmetic, polynomials vs exponentials, logarithms in any base differ by a constant factor (`log_b n = lg n / lg b` — so O-notation never writes the base), factorials (Stirling: `lg(n!) = Θ(n lg n)` — the sorting lower bound of Chapter 8, pre-loaded), the iterated logarithm lg* n (how many times you must lg before dropping ≤ 1: lg* 2⁶⁵⁵³⁶ = 5 — 65536 → 16 → 4 → 2 → 1), Fibonacci (F_n ≈ φⁿ/√5 with φ ≈ 1.618 — the worst-case depth of Euclid's algorithm and of naive AVL analysis).
