Chapter 6 builds the heap — an array pretending to be a binary tree — then uses it twice: to sort (heapsort, O(n lg n) worst case, in place) and as a priority queue.

## The heap

A (binary) heap is an array with a shape: the tree it represents is complete — every level full except possibly the last, filled left to right. Because of that shape, no pointers are needed:

- `PARENT(i) = ⌊i/2⌋`, `LEFT(i) = 2i`, `RIGHT(i) = 2i+1`
- **max-heap property:** a node's key is ≥ its children's keys (min-heap: ≤)

Height is Θ(lg n) — that number is the cost of everything vertical in this chapter.

## 6.2 MAX-HEAPIFY

The repair primitive: given that i's two subtrees are already max-heaps but `A[i]` might violate the property, sift `A[i]` down — swap with the larger child, recurse. Cost O(lg n) worst case (a leaf-to-root path). The loop-invariant habit from Chapter 2 gets reused on the recursion here.

## 6.3 BUILD-MAX-HEAP — the linear surprise

Heapify the array bottom-up: run MAX-HEAPIFY on nodes `⌊n/2⌋` down to 1 (leaves are already heaps). The invariant: nodes `i+1..n` are roots of max-heaps when iteration i starts.

Running time looks like `n/2 · O(lg n) = O(n lg n)`, but that's loose. Most nodes sit near the bottom where the sift-down is short: at most `⌈n/2^(h+1)⌉` nodes have height h, so

```
Σ n/2^(h+1) · O(h) = O(n Σ h/2^h) = O(2n) = O(n)
```

— the geometric sum kills it. **Building a heap is linear.** This is the chapter's one genuinely surprising bound.

## 6.4 Heapsort

Build a max-heap, then repeatedly swap the root (the max) with the last element, shrink the heap by one, and sift the new root down. The tail of the array becomes the sorted output; Θ(n lg n) worst case, O(1) extra space. In practice quicksort usually still wins on constants — the heap's value is the structure, not the sort.

## 6.5 Priority queues

The heap's real career. A max-priority queue supports INSERT, MAXIMUM, EXTRACT-MAX, INCREASE-KEY — all O(lg n) (INSERT and INCREASE-KEY sift *up* a leaf-to-root path). Implementation detail the book flags: real applications keep *handles* between heap slots and their objects, updated on every swap — that's `heapq` plus a position map.

Event-driven simulation, schedulers, Dijkstra (Ch. 24) and Prim (Ch. 23) all rest on this: "give me the best frontier node next."
