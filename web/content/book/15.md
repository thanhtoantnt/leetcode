The biggest folder in this repo (`dynamic/`, 17 solutions) is this chapter's training ground. DP applies when subproblems **overlap** — divide-and-conquer re-solves the shared subsubproblems; DP solves each once and reads the table.

## 15.1 Rod cutting

Cut a length-n rod into integer pieces to maximize total price. Naive recursion `CUT-ROD` runs in Θ(2ⁿ) — not because the problem is exponential (the distinct subproblems are only n), but because the recursion tree re-solves the same lengths endlessly.

The fix, two flavors of the same table:

- **Top-down with memoization** — keep the recursion, cache `r[n]` on first computation. Same shape as `@lru_cache`.
- **Bottom-up** — fill `r[0..n]` in order of size, so every subresult exists before it's read.

`r_n = max(p_n, r_1 + r_{n-1}, ..., r_{n-1} + r_1)` — or the cleaner one-cut form `r_n = max_{1≤i≤n}(p_i + r_{n-i})`. To recover the *actual* cuts, keep a companion `s[n]` table of the best first cut and walk it off the end. The reconstruction table is a standard trick: DP gives you the value for free; the solution costs one extra array.

## 15.2 Matrix-chain multiplication

Parenthesize `A₁A₂⋯Aₙ` to minimize scalar multiplications (a p×q times q×r matrix costs pqr). Order doesn't change the product's value, only its cost — dramatically.

Subproblems are *chains* `Aᵢ..Aⱼ`: `m[i,j] = min over k of m[i,k] + m[k+1,j] + p_{i-1}p_k p_j`. Fill by chain length, `s[i,j]` stores the winning k. Θ(n³) time, Θ(n²) space. The lesson: when prefixes alone don't close (the second subproblem `A_{k+1}..A_j` isn't a prefix), widen the subproblem space to intervals — exactly the "state = (i, j)" move of edit-distance/LCS-style problems.

## 15.3 The two required properties

- **Optimal substructure** — an optimal solution contains optimal solutions to subproblems. Provable by the cut-and-paste argument: swap in a better subproblem solution, paste, contradict optimality.
- **Overlapping subproblems** — the recursion revisits the same states; a table pays off. (Fibonacci: n states; rod cutting: n; matrix-chain: Θ(n²). Count states × choices-per-state = running time — the subproblem graph gives it directly.)

The counterexample to memorize: **longest simple path** has no optimal substructure — the longest path q→t doesn't contain longest paths q→r, r→t, because the subpaths interfere (they may need to share vertices). Shortest path is fine (subpaths of shortest paths are shortest, and independent); longest simple path is NP-hard. Independence of subproblems is what makes cut-and-paste work.

## 15.4 Longest common subsequence

`LCS(X, Y)` — the canonical two-sequence DP, `c[i,j]` over prefix pairs:

```
if x_i == y_j:  c[i,j] = c[i-1,j-1] + 1
else:           c[i,j] = max(c[i-1,j], c[i,j-1])
```

Θ(mn) time and space (space reducible to O(min(m,n)) if only the length is needed — reconstruction needs the full table or the clever Hirschberg trick). DNA similarity, diff tools, edit distance's cousin — `dynamic/1143` in this repo, visualized as the filling of the c table.
