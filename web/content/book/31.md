Number theory for algorithms: modular arithmetic, Euclid's gcd, and the RSA cryptosystem — with primality testing and factoring as the asymmetric hardness the whole thing rests on.

## 31.1–31.3 The toolkit

Z_n, gcd, and the theorems that matter: Fermat's little theorem (a^(p−1) ≡ 1 mod p for prime p), Euler's theorem, modular inverses exist iff gcd(a,n)=1. **Euclid's algorithm**: gcd(a,b) = gcd(b, a mod b) — O(lg b) iterations (Fibonacci is the worst case, again the golden ratio). The **extended** version also returns x,y with ax+by = gcd(a,b), which computes modular inverses and solves linear congruences — `maths/` problems asking "find x mod m" live here.

**Modular exponentiation**: square-and-multiply, O(lg e) multiplications — the same doubling trick as fast power (`maths/0050`-style, `pow(x, e, mod)`).

## 31.7 RSA

Public key (e, n=pq), private key d with ed ≡ 1 mod φ(n). Encrypt c = M^e mod n; decrypt M = c^d mod n. Correctness because M^(ed) ≡ M mod n for all M (by Fermat/Euler on both primes via CRT). Security rests on: computing d needs φ(n), which needs **factoring n** — believed hard. Everything else in the pipeline (key generation, encryption, decryption) is polynomial. Hybrid usage in practice: RSA exchanges a symmetric key, the symmetric cipher carries the bulk.

## 31.8 Primality testing

Generate a random β-bit number; by the prime number theorem it's prime with probability ≈ 1/ln n, so ~ln n trials find one — primality must be fast. Fermat test: a^(n−1) ≡ 1? Composites passing for all bases are Carmichael numbers (561, 1105, 1729), so the test needs strengthening: **Miller-Rabin** checks for nontrivial square roots of 1 along the way. Randomized with s bases, error ≤ 4^−s for *every* input — Chapter 5's randomized-algorithm design at its best. (A deterministic poly-time test exists — AKS — but Miller-Rabin wins in practice.)

## 31.9 Factoring

Pollard's rho: iterate x²+1 mod n, track gcd(|x_i − x_2i|, n); the birthday-paradox collision structure finds small factors in ~n^(1/4). Heuristic, tiny memory, devastating on unfactored RSA moduli with small factors. The best general algorithms run ~exp(cuberoot(bits)) — sub-exponential, super-polynomial: the gap RSA lives in.
