Quicksort is the chapter about one bad idea in a great algorithm: worst case Θ(n²), yet it is usually the fastest comparison sort in practice — small constants, in-place, expected Θ(n lg n) on every input once randomized.

## 7.1 Partition

Divide-and-conquer again, but the work is front-loaded into the divide step:

- **Divide:** `PARTITION(A, p, r)` picks pivot `x = A[r]` and rearranges `A[p..r]` in place so that everything ≤ x comes first, x lands at its final slot q, everything > x follows. Θ(n).
- **Conquer:** recurse on `A[p..q-1]` and `A[q+1..r]`.
- **Combine:** nothing — the subarrays are already in place.

PARTITION is two index runners: `j` scans, `i` marks the end of the ≤ region. When `A[j] ≤ x`, increment i and swap. The loop invariant is the four-region picture — `A[p..i] ≤ x`, `A[i+1..j-1] > x`, `A[r] = x`, `A[j..r-1]` unknown. Same "grow a classified region" invariant as every two-pointer problem in `two_pointers/`.

## 7.2 Why it's fast or slow

Everything depends on split balance:

- **Worst** — every split is n−1 / 0 (e.g. sorted input with the last element as pivot): `T(n) = T(n-1) + Θ(n)` = Θ(n²), no better than insertion sort.
- **Best** — even splits: merge sort's recurrence, Θ(n lg n).
- The robust fact: a bad split followed by a good split costs the same as one balanced split of the combined range — an 9:1 split is still "fine." Only *consistently* terrible pivots hurt.

## 7.3 Randomization

Don't trust the input's order — impose one. Swap a uniformly random element into the pivot slot (random sampling). Now no input can reliably trigger the worst case; the guarantee is over the algorithm's coin flips, not the input distribution (Chapter 5's average-case vs expected distinction, in production).

## 7.4 The analysis

Worst case: substitution on `T(n) = max_q (T(q) + T(n-q-1)) + Θ(n)` gives O(n²), and Ω(n²) is easy.

Expected: indicator variables again — `X_ij` = "i and j are ever compared." Each pair is compared at most once (only common ancestors compare them), and it happens only if one of them is the first pivot chosen from their interval, probability `2/(j-i+1)`. Summing `Σ 2/(j-i+1) = O(n lg n)`. A randomized algorithm whose expected cost is Θ(n lg n) with tiny constants, in place — that's why library sorts are quicksort variants (introsort: quicksort that falls back to heapsort when recursion goes deep).
