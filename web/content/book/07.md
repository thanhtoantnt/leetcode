Quicksort is the chapter about one bad idea in a great algorithm: worst case Θ(n²), yet it is usually the fastest comparison sort in practice — small constants, in-place, expected Θ(n lg n) on every input once randomized.

## 7.1 Partition

Divide-and-conquer again, but the work is front-loaded into the divide step:

- **Divide:** `PARTITION(A, p, r)` picks pivot `x = A[r]` and rearranges `A[p..r]` in place so that everything ≤ x comes first, x lands at its final slot q, everything > x follows. Θ(n).
- **Conquer:** recurse on `A[p..q-1]` and `A[q+1..r]`.
- **Combine:** nothing — the subarrays are already in place.

```text
PARTITION(A, p, r)
1  x = A[r]                        // the pivot
2  i = p − 1                       // end of the ≤ region
3  for j = p to r − 1
4      if A[j] ≤ x
5          i++;  swap A[i] ↔ A[j]  // grow the ≤ region by one
6  swap A[i+1] ↔ A[r]              // pivot to its final slot
7  return i + 1
```

Two runners: `j` scans, `i` marks the end of the ≤ region. The book's Figure 7.1 on `[2, 8, 7, 1, 3, 5, 6, 4]` (pivot 4):

```text
j scans:  2 ≤ 4 → swap with itself        [2 | 8 7 1 3 5 6 | 4]
          8 > 4 → skip
          7 > 4 → skip
          1 ≤ 4 → i=1, swap(8,1)          [2 1 | 7 8 3 5 6 | 4]
          3 ≤ 4 → i=2, swap(7,3)          [2 1 3 | 8 7 5 6 | 4]
          5,6 > 4 → skip
final:    swap(8, 4) → [2 1 3 | 4 | 8 7 5 6]   q = 4th slot
                   ≤ pivot   ↑   > pivot
```

The pivot lands at index q **and never moves again** — its position is final after one pass. The loop invariant is the four-region picture — `A[p..i] ≤ x`, `A[i+1..j-1] > x`, `A[r] = x`, `A[j..r-1]` unknown — the same "grow a classified region" invariant as every two-pointer problem in `two_pointers/`.

## 7.2 Why it's fast or slow

Everything depends on split balance:

```text
balanced (best):              degenerate (worst):
        n                              n
      /   \                           /
   n/2     n/2                      n−1
   …      …                        /
  Θ(n) per level, lg n levels    Θ(n) per level, n levels
  = Θ(n lg n)                    = Θ(n²)
```

- **Worst** — every split is n−1 / 0 (e.g. *sorted* input with the last element as pivot — the classic trap): `T(n) = T(n-1) + Θ(n)` = Θ(n²), no better than insertion sort.
- **Best** — even splits: merge sort's recurrence, Θ(n lg n).
- The robust fact: a bad split followed by a good split costs the same as one balanced split — a 9:1 split is still "fine" because the next split inside the big side repays it. Only *consistently* terrible pivots hurt.

## 7.3 Randomization

Don't trust the input's order — impose one. Swap a uniformly random element into the pivot slot. Now no input can reliably trigger the worst case; the guarantee is over the algorithm's coin flips, not the input distribution (Chapter 5's average-case vs expected distinction, in production).

## 7.4 The analysis

Worst case: substitution on `T(n) = max_q (T(q) + T(n-q-1)) + Θ(n)` gives O(n²), and Ω(n²) is easy.

Expected Θ(n lg n) — the indicator-variable argument, unpacked:

```text
Xij = I{elements i and j are ever compared}     (sorted order positions)

1. Each pair is compared at most once: only a pivot that is an
   ancestor of both compares them, and after that pivot splits them
   apart forever.  So E[comparisons] = Σᵢ<ⱼ Pr[i vs j].

2. Pr[i vs j] = 2/(j−i+1): within the interval {i,…,j}, i and j get
   compared only if the FIRST pivot chosen from that interval is
   i or j (any interior pivot separates them unpunished; a pivot
   outside never touches the pair).

3. Σᵢ<ⱼ 2/(j−i+1) ≈ n · Σₖ 2/k = O(n lg n)     ∎
```

A randomized algorithm whose expected cost is Θ(n lg n) with tiny constants, in place — that's why library sorts are quicksort variants (introsort: quicksort that falls back to heapsort when recursion goes too deep, capping the worst case at O(n lg n) while keeping quicksort's constants — C++ `std::sort` exactly).
