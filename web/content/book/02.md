Chapter 2 is where the book starts proving things. Two sorting algorithms — insertion sort and merge sort — carry the whole framework: pseudocode, loop invariants, the RAM model, worst/average/best case, and divide-and-conquer.

## 2.1 Insertion sort

Sort the way you sort a hand of cards: take one card at a time off the pile, slide it into its correct spot among the already-sorted cards in your left hand.

For array `A[1..n]`, each iteration of the outer loop takes `key = A[j]` and shifts the sorted prefix `A[1..j-1]` right until the key's slot opens up. It sorts in place.

**Loop invariant:** at the start of each iteration, `A[1..j-1]` is the original elements from positions 1..j-1, now in sorted order. Three properties make it work, and this checklist is reused for every correctness proof in the book:

- **Initialization** — it holds before the first iteration (one element is trivially sorted).
- **Maintenance** — if it holds before an iteration, it holds after (the insertion keeps the prefix sorted).
- **Termination** — when the loop stops, the invariant plus the loop's exit condition gives the result (`j = n+1`, so the whole array is sorted).

This is induction in disguise: base case, inductive step, and a place where the induction stops.

## 2.2 Analyzing algorithms

Analysis needs a model of computation. The book uses **RAM** — random-access machine: one instruction at a time, each instruction takes constant time, constant number of registers, memory access is uniform. No caches, no pipelines, no "sort" instruction. The gray areas (is `2^k` constant-time? yes, when k fits a word) are acknowledged but mostly dodged.

Running time = number of primitive operations. For insertion sort the cost depends on the input, not just n:

- **Worst case** (reverse-sorted): the inner while loop runs fully every time → `an² + bn + c` → Θ(n²).
- **Best case** (already sorted): the while test fails immediately → Θ(n).
- **Average case** (all orderings equally likely): about half the inversions of worst case → Θ(n²).

The book's working rule: analyze the worst case — it's a blanket guarantee, inputs are rarely adversarial, and for insertion sort the average is no better asymptotically anyway. Θ-notation gets a first informal pass here: drop lower-order terms and the leading constant.

## 2.3 Designing algorithms — merge sort

Divide-and-conquer arrives for real:

- **Divide** the array in half.
- **Conquer** each half by recursing (base case: 1 element).
- **Combine** by merging two sorted halves in linear time.

`MERGE` walks two pointers through the sorted halves, always emitting the smaller head. With a sentinel `∞` at each end, no bounds checks are needed. The recurrence is

```
T(n) = 2T(n/2) + Θ(n)  →  Θ(n lg n)
```

which the book solves by a picture: the recursion tree has lg n + 1 levels, each level doing Θ(n) total work. That tree picture *is* the master method you'll meet in Chapter 4.

Why bother with merge sort when insertion sort is simpler? n² vs n lg n: at n = 10⁶ that's 10¹² vs ~2·10⁷ basic operations. Same lesson as Chapter 1's computer-A-vs-B story.
