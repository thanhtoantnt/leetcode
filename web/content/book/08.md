Chapter 8 proves a wall, then walks around it. Merge sort, heapsort, quicksort are all comparison sorts — and no comparison sort can beat Θ(n lg n). Counting, radix, and bucket sort escape by *not comparing*: they use the values themselves as addresses.

## 8.1 The Ω(n lg n) lower bound

Model any comparison sort as a **decision tree**: internal nodes are comparisons `a_i ≤ a_j`, leaves are the output permutations. One execution = one root-to-leaf path, so worst-case comparisons = tree height.

The tree must reach all n! permutations as leaves (each must be producible by some input). A binary tree of height h has ≤ 2^h leaves, so

```
n! ≤ 2^h  →  h ≥ lg(n!) = Ω(n lg n)   (Stirling: lg n! ~ n lg n)
```

Merge sort and heapsort are therefore asymptotically optimal *among comparison sorts*. The bound is about the model, not cleverness — you can't decisions-tree your way to a linear comparison sort.

## 8.2 Counting sort

Assume integers in `0..k`. Count occurrences into `C[0..k]`, prefix-sum C so `C[v]` = number of elements ≤ v, then walk the input *backwards* placing `A[j]` at `B[C[A[j]]]` and decrementing. Θ(n + k), which is Θ(n) when k = O(n).

Two things worth noticing:

- **No comparisons anywhere** — the value indexes the array, which is exactly why §8.1 doesn't apply.
- **Stable** — equal elements keep their input order (that's what the backward walk buys). Stability is not a nicety; it's the load-bearing property of the next algorithm.

## 8.3 Radix sort

Sort b-bit numbers by d = ⌈b/r⌉ passes of a stable sort on r-bit digits, least significant digit first. Each pass must be stable — that's what lets an earlier (more significant) pass have the final say while later passes only break ties. The punchline card: sorting dates by day, then month, then year.

Cost: `Θ((b/r)(n + 2^r))`. Choosing `r = lg n` gives Θ(b·n/lg n) — linear when b = O(lg n). Digit-at-a-time thinking also powers the `bit_manipulate/` tricks in this repo.

## 8.4 Bucket sort

Input uniform in [0,1): drop each key into bucket `⌊n·A[i]⌋`, insertion-sort each bucket, concatenate. Expected Θ(n) — because *uniform*, each bucket holds O(1) elements in expectation. The proof is Chapter 5's machinery verbatim: `n_i = Σ X_ij` indicators, `E[n_i²] = 2 − 1/n`, linearity of expectation over the buckets' quadratic insertion-sort costs.

The recurring trade of the whole chapter: assume something about the input (small range / fixed width / uniform distribution), get linear time. The comparison-sort wall stands only for inputs about which you know nothing.
