Disjoint sets — union-find — maintains a partition under two operations: FIND-SET (which group is x in?) and UNION (merge two groups). Nearly the whole repo's `union-find/` folder and half of `graphs/` rest on this one structure.

## 21.1 The operations and the killer app

MAKE-SET(x), UNION(x,y), FIND-SET(x) — representatives identify sets. The canonical use is CONNECTED-COMPONENTS: make a set per vertex, then for each edge, union the endpoints' sets. Afterwards, same component ⟺ same set. Process edges incrementally and you have a fully dynamic connectivity oracle — Kruskal's MST (Ch. 23) is exactly this loop run in edge-weight order.

## 21.2 Linked lists — and why to skip them

Each set is a linked list; UNION appends one list to another, updating every element's back-pointer. Worst case Θ(n²) total (repeatedly appending long lists onto short is the trap). The **weighted-union heuristic** — always append the shorter list — makes it O(n lg n) total by the doubling argument: an element's pointer can only be updated lg n times, because each update at least doubles its set's size. Nice proof, obsolete implementation.

## 21.3 Disjoint-set forests — the real thing

Each set is a rooted tree of parent pointers; the root is the representative. FIND-SET walks parents up; UNION points one root at the other. Two heuristics, individually good, jointly near-perfect:

- **Union by rank** — attach the lower-rank root under the higher (rank ≈ height bound). Keeps trees shallow.
- **Path compression** — during FIND-SET, make every node on the walked path point directly to the root. The two-pass trick (up to find, down to re-point), 3 lines of code.

## 21.4 The α(n) bound

With both heuristics, m operations on n elements run in **O(m α(n))** — amortized, via the potential method (Ch. 17). α is the inverse of the Ackermann-like function A_k: A₄(1) already exceeds the atoms in the universe, so α(n) ≤ 4 for anything that fits in memory. Linear in practice, superlinear in theory. There's a matching Ω(m α(n)) lower bound — union-find is *exactly* this hard, no structure can do better.
