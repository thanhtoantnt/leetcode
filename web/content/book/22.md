The `graphs/` folder's foundation: how to represent graphs, and the two searches — BFS and DFS — from which almost everything else (topological sort, SCCs, shortest paths, MST algorithms) is derived.

## 22.1 Representations

- **Adjacency list**: array of lists; Θ(V+E) space, iterate neighbors cheaply. Default for sparse graphs and all LeetCode work.
- **Adjacency matrix**: Θ(V²) space, O(1) edge test. Right for dense graphs or Floyd-Warshall (Ch. 25).

## 22.2 Breadth-first search

Explore in rings: visit s, then everything 1 edge away, then 2, ... A FIFO queue holds the frontier; color/GREY bookkeeping prevents revisits. Θ(V+E).

The payoff: **BFS computes shortest paths in edge count** — when u is discovered from v, `u.d = v.d + 1` is exactly the unweighted distance, and the predecessor pointers form a BFS tree. Proof by the queue's monotonicity: d values leave the queue in nondecreasing order. This is Dijkstra's skeleton with all weights = 1 (visualized in this repo: `BFS/0542_01-matrix` — multi-source BFS).

## 22.3 Depth-first search

Explore one branch fully before backtracking; a stack (explicit or the call stack). Θ(V+E), but with the bookkeeping that powers everything: **discovery time u.d and finish time u.f** — timestamps from a global counter.

The parenthesis theorem: on any path, intervals [u.d, u.f] are either disjoint (no ancestor relation) or nested (descendant). White/gray/black coloring detects cycles: a gray→gray edge (back edge) means a cycle. A DAG has no back edges — the basis of topological sort.

## 22.4 Topological sort

Run DFS on a DAG, output vertices by *decreasing finish time*. Why it works: for every edge (u,v) in a DAG, u finishes after v — so the reverse-finish order puts u before v. Linear order of dependencies, in Θ(V+E). The pre-req-ordering problem: `graphs/` course-schedule solutions are exactly this (with cycle detection via back edges as the failure case).

## 22.5 Strongly connected components

Mutually reachable vertex groups. **Kosaraju**: (1) DFS on G computing finish times, (2) DFS on the transpose G^T in decreasing finish order — each DFS tree in the second pass is one SCC. Two DFS passes, linear time. The magic: the first pass finds an ordering where the component graph (a DAG) is topologically sorted, so the second pass can't leak across components.
