Minimum spanning tree: connect all vertices of a weighted undirected graph as cheaply as possible. Greedy works perfectly here — the chapter proves it, with matroid theory (Ch. 16.4) explaining why.

## 23.1 The generic method and the cut theorem

Grow a set A that is always a subset of some MST. An edge is **safe** when A ∪ {e} is still contained in an MST.

**The cut theorem:** partition vertices into (S, V−S) with no A-edge crossing it (the cut *respects* A). Then the **light edge** crossing the cut — minimum weight among crossers — is safe. Proof: take an MST T containing A; if it lacks the light edge (u,v), the tree path from u to v must cross the cut somewhere (x,y); swap (x,y) out for (u,v) — same connection, weight no larger, still spanning. Exchange argument, again.

Every correct MST algorithm is a strategy for picking cuts and light edges.

## 23.2 Kruskal and Prim

**Kruskal** — sort all edges by weight; take each edge unless its endpoints are already connected (union-find, Ch. 21). The cut is implicit: each component is one side; the smallest edge leaving it gets taken. O(E lg E), dominated by the sort. Kruskal = sorted edges + cycle rejection via FIND-SET.

**Prim** — grow one tree from a root; repeatedly add the cheapest edge leaving the tree. Maintains a key per frontier vertex (min edge weight into the tree) in a priority queue — Dijkstra's exact shape. Binary heap: O(E lg V); Fibonacci heap: O(E + V lg V) (Ch. 19's payoff).

Which to use: Kruskal for sparse graphs (sort-bound), Prim for dense (a good heap makes it E + V lg V ≈ V², while Kruskal sorts E = V² edges). On LeetCode, Kruskal with union-find is the common ask; "min cost to connect all points" is MST verbatim.

## Why greedy is provably fine here

The spanning-forest sets form a **matroid** (independent = acyclic), and greedy is optimal on matroids — the same theorem that validates Chapter 16's activity selection generalizes. MST is the case where the greedy proof is so clean it fits in a paragraph.
