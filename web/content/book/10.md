The toolbox chapter: stacks, queues, linked lists, and rooted trees — the pointer-based structures everything later sits on. All operations here are O(1) or Θ(n)-scan; the point is the *representation*, not the analysis.

## 10.1 Stacks and queues

A stack is an array plus one integer. `S.top` marks the top; PUSH writes at `top+1`, POP reads and decrements. LIFO — last in, first out. Overflow (top > n) and underflow (pop empty) are the only failure modes.

A queue is an array plus two integers, `head` and `tail`. ENQUEUE writes at the tail, DEQUEUE reads at the head, and both wrap around modulo `n` — a circular buffer. FIFO. The subtlety is the full/empty test: with plain counters, `head == tail+1` means full.

Both support every operation in O(1). The classic exercises — queue via two stacks (amortized, Chapter 17's warmup), stack via two queues — are interview staples.

Why a stack matters more than its simplicity suggests: recursion *is* a stack (the call stack), DFS is a stack you can see, and the monotonic-stack problems in `stacks/` are "keep the stack sorted while pushing" in disguise.

## 10.2 Linked lists

A doubly linked list gives each node `prev`/`next` pointers; `L.head` points at the first. LIST-INSERT and LIST-DELETE are O(1) *given a pointer to the node* — no shifting, unlike arrays. LIST-SEARCH is a Θ(n) walk. Sentinels (a dummy node standing in for NIL) remove the boundary special-cases from the code — the same trick red-black trees formalize.

Arrays vs lists, the honest version: arrays give O(1) indexed access and terrible middle insertion; lists give O(1) insertion/deletion at a known node and no indexed access. The `linked_list/` solutions are mostly pointer surgery — reverse a list (iteratively with three rolling pointers), find the cycle (fast/slow runners), merge two sorted lists.

## 10.3 Implementing pointers with arrays

Objects and pointers are a convenience, not a requirement: three parallel arrays `key[]`, `next[]`, `prev[]` simulate any linked structure, with integers as pointers. This is what languages without pointers do, what arena allocators do, and — worth noticing — exactly how the heap in Chapter 6 worked all along (index arithmetic instead of pointers).

## 10.4 Rooted trees

Binary tree: each node holds `p`, `left`, `right`. For unbounded branching, **left-child, right-sibling**: each node points to its first child and its next sibling — any rooted tree in two pointers per node. This representation resurfaces in trie and DOM-style structures (`trees/` problems build both shapes).
