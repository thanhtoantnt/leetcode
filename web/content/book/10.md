The toolbox chapter: stacks, queues, linked lists, and rooted trees — the pointer-based structures everything later sits on. All operations here are O(1) or Θ(n)-scan; the point is the *representation*, not the analysis.

## 10.1 Stacks and queues

A stack is an array plus one integer. `S.top` marks the top; PUSH writes at `top+1`, POP reads and decrements. LIFO — last in, first out. Overflow (top > n) and underflow (pop empty) are the only failure modes.

```text
PUSH 3, PUSH 7, PUSH 1:   [3 7 1]        top
POP → 1:                  [3 7]        top
PUSH 9:                   [3 7 9]        top
every operation: O(1), one integer's worth of state
```

A queue is an array plus two integers, `head` and `tail`. ENQUEUE writes at the tail, DEQUEUE reads at the head, and both wrap around modulo n — a **circular buffer**:

```text
capacity 6, head=1 tail=4 after pushing a b c (…) and popping one:

[a b c . . .]        head→1 (gone), tail→4
      head    tail
ENQUEUE d, e:      [a b c d e .]   tail wraps: next write at slot 0
DEQUEUE b, c, d, e, then ENQUEUE f:
[. . . d e f]  → after pops + f: [f . . . . .] with head chasing tail around
full vs empty: plain head==tail is ambiguous — keep a count or burn one slot
```

Both support every operation in O(1). The classic exercise — **queue via two stacks** — is Chapter 17's warmup, and the trick is worth seeing once:

```text
INBOX (newest on top)      OUTBOX (oldestiest on top)
push a b c:  [a b c]
dequeue:  inbox empty → pour: reverse everything
            [a b c]  ⇒  outbox [c b a]   pop a ✓  O(n) once
dequeue:  outbox nonempty → pop b ✓      O(1)
each element crosses at most once ⇒ amortized O(1) per op (Ch. 17)
```

Why a stack matters more than its simplicity suggests: recursion *is* a stack (the call stack), DFS is a stack you can see, and the monotonic-stack problems in `stacks/` are "keep the stack sorted while pushing" in disguise.

## 10.2 Linked lists

A doubly linked list gives each node `prev`/`next` pointers; `L.head` points at the first. LIST-INSERT and LIST-DELETE are O(1) *given a pointer to the node* — three pointer rewrites, no shifting, unlike arrays. LIST-SEARCH is a Θ(n) walk. Sentinels (a dummy node standing in for NIL) remove the boundary special-cases from the code — the same trick red-black trees formalize.

Arrays vs lists, the honest version: arrays give O(1) indexed access and terrible middle insertion; lists give O(1) insertion/deletion at a known node and no indexed access.

## 10.3 Implementing pointers with arrays

Objects and pointers are a convenience, not a requirement: three parallel arrays `key[]`, `next[]`, `prev[]` simulate any linked structure, with integers as pointers. This is what languages without pointers do, what arena allocators do, and — worth noticing — exactly how the heap in Chapter 6 worked all along (index arithmetic instead of pointers).

## 10.4 Rooted trees

Binary tree: each node holds `p`, `left`, `right`. For unbounded branching, **left-child, right-sibling**: each node points to its first child and its next sibling — any rooted tree in two pointers per node:

```text
        A                    A
      / | \        ⇒       A.next=NULL
     B  C  D              A.child=B   B.sibling=C  C.sibling=D
   / \                    B.child=E   B.sibling→C (not a child edge!)
  E   F                   E.sibling=F
```

This representation resurfaces in trie and DOM-style structures (`trees/` problems build both shapes).
