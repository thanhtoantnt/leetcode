Chapter 4 formalizes divide-and-conquer and gives three tools for solving the recurrences it produces. The running example, the maximum-subarray problem, is LeetCode 53 — solved in this repo.

## The pattern

Divide the input into smaller instances of the same problem, conquer them recursively (base case: solve small instances directly), combine the results. When a subproblem is not quite the same as the original — like "maximum subarray that must cross the midpoint" — the book counts it as part of combine.

## 4.1 Maximum subarray (LeetCode 53)

The stock framing: given daily price changes, find the contiguous run with the largest sum. Brute force is Θ(n²). Divide-and-conquer gets Θ(n lg n):

Split at `mid`. Any subarray lies entirely left, entirely right, or **crosses the midpoint**. The first two are recursive calls. The crossing case is linear: best suffix of the left half ending at `mid` plus best prefix of the right half starting at `mid+1` — scan outward from the middle on each side. Return the max of the three.

The takeaway is the shape, not this particular algorithm: the combine step is allowed to be a *different* linear-time computation, not a merge.

This repo keeps the one-pass Kadane version (`dynamic/0053_maximum-subarray.py`, O(n)), which is what you'd actually submit — the divide-and-conquer version is here to teach recursion structure.

## Recurrences

Divide-and-conquer cost: `T(n) = a·T(n/b) + f(n)` — a subproblems of size n/b, plus divide/combine cost f(n). The chapter's three solving methods:

1. **Substitution** — guess the answer, prove by induction. Tighten the guess with a smaller constant or subtract a lower-order term when the induction won't close. Most flexible, least mechanical.
2. **Recursion tree** — draw the levels, sum each level, sum the levels. `2T(n/2) + Θ(n)` is lg n levels × Θ(n) per level = Θ(n lg n). The intuition behind the next method.
3. **Master method** — the cookbook. For `T(n) = aT(n/b) + f(n)`, compare `f(n)` against `n^(log_b a)` (the "work at the leaves" threshold):
   - f grows polynomially slower → `T = Θ(n^(log_b a))`
   - f matches (up to log factors, the regularity condition) → `T = Θ(n^(log_b a) · lg n)`
   - f grows polynomially faster *and* is regular → `T = Θ(f(n))`

Merge sort hits case 2 (leaves and each level balance). Strassen's matrix multiply is the celebrity: split matrices into quadrants, 7 clever half-size products instead of 8 → `T(n) = 7T(n/2) + Θ(n²)` → Θ(n^lg 7) ≈ Θ(n^2.81). It stays below the naive Θ(n³) forever, the same way n lg n stays below n².

Technicalities the book waves away, and so should you: floors/ceilings on n/2, and boundary conditions — they change constants, not growth rates.
