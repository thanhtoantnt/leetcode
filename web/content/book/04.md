Chapter 4 formalizes divide-and-conquer and gives three tools for solving the recurrences it produces. The running example, the maximum-subarray problem, is LeetCode 53 — solved in this repo.

## The pattern

Divide the input into smaller instances of the same problem, conquer them recursively (base case: solve small instances directly), combine the results. When a subproblem is not quite the same as the original — like "maximum subarray that must cross the midpoint" — the book counts it as part of combine.

## 4.1 Maximum subarray (LeetCode 53)

The stock framing: given daily price changes, find the contiguous run with the largest sum. Brute force is Θ(n²) (every start × every end). Divide-and-conquer gets Θ(n lg n):

Split at `mid`. Any subarray lies entirely left, entirely right, or **crosses the midpoint**. The first two are recursive calls. The crossing case is linear — best suffix of the left half ending at `mid`, plus best prefix of the right half starting at `mid+1`, each found by one scan outward from the middle:

```text
changes:   [−3, 16, −7,  4,  −8, 13,  −9,  2]
           └──── left half ────┘  └──── right half ────┘

best suffix of left, ending at 4   (scan right-to-left, accumulate)
   4 → 4−7 = −3 (best 4) → −3+16 = 13 (best 13) → 13−3 = 10
   best = 13          [16,−7,4]
best prefix of right, from −8      (scan left-to-right, accumulate)
   −8 → −8+13 = 5 (best 5) → 5−9 = −4 → −2
   best = 5           [−8,13]
crossing = 13 + 5 = 18             [16,−7,4,−8,13]

recursive answers: left = 16 ([16]), right = 13 ([13])
max(16, 13, 18) = 18 ✓
```

The takeaway is the shape, not this particular algorithm: the combine step is allowed to be a *different* linear-time computation, not a merge. This repo keeps the one-pass Kadane version (`dynamic/0053`, O(n)) — the flipbook there animates exactly these running sums.

## Recurrences — the chapter's three tools

Divide-and-conquer cost: `T(n) = a·T(n/b) + f(n)` — a subproblems of size n/b, plus divide/combine cost f(n).

**1. Substitution** — guess the answer, prove by induction. The classic: `T(n) = 2T(n/2) + n`, guess `T(n) ≤ cn lg n`:

```text
assume T(k) ≤ ck lg k for k < n.  Then
T(n) ≤ 2·c(n/2)·lg(n/2) + n
     = cn lg n − cn lg 2 + n        [lg(n/2) = lg n − 1]
     = cn lg n − cn + n
     ≤ cn lg n                       ⟺  n ≤ cn  ✓ for c ≥ 1   ∎
```

Two rescue moves when the induction won't close: use a smaller c, or strengthen the guess by subtracting a lower-order term (guess `T(n) ≤ cn lg n − dn` for recurrences like `2T(n/2) + 1`). Proving an upper bound inductively needs the bound to have *slack* at small n — subtracting a negative helps, counterintuitively.

**2. Recursion tree** — draw the levels, sum each level, sum the levels. For `T(n) = 3T(n/4) + cn`:

```text
              cn²                    per level: n(3/4)^ℓ — geometric decay
        /        |        \
     cn(3/4)   cn(3/4)   cn(3/4)     total internal work < 4cn... 
   …                                     height log₄ n, leaves 3^log₄ n
   ○ ○ ○ … 3^log₄ n leaves, each Θ(1)    = n^log₄ 3 ≈ n^0.79
   leaves DOMINATE → Θ(n^0.79)
```

Top-heavy trees (a/b > 1) are leaf-dominated; balanced trees charge every level equally (merge sort); bottom-heavy trees are root-dominated.

**3. Master method** — the cookbook, comparing `f(n)` against `n^(log_b a)` (the leaf threshold):

| Case | Condition | Answer | Concrete |
|---|---|---|---|
| 1 | f polynomially smaller | Θ(n^(log_b a)) | `9T(n/3) + n` → Θ(n²) |
| 2 | f = Θ(n^(log_b a) lg^k n) | Θ(n^(log_b a) lg^(k+1) n) | `2T(n/2) + n` → Θ(n lg n) |
| 3 | f polynomially larger + regularity | Θ(f(n)) | `2T(n/2) + n²` → Θ(n²) |

The friendliest case-2 instance is binary search: `T(n) = T(n/2) + 1` → a=1, b=2, leaves = n^0 = 1, f = 1 matches → **Θ(lg n)** — three symbols that justify every `O(log n)` you've ever said about 0704.

## Strassen — the celebrity

Matrix multiply by blocks: eight half-size products give Θ(n³) (same exponent, bookkeeping only). Strassen's idea: **seven** clever half-size products, at the price of extra Θ(n²) adds:

```text
M1 = (a11 + a22)(b11 + b22)      M5 = (a11 + a12) b22
M2 = (a21 + a22) b11             M6 = (a21 − a11)(b11 + b12)
M3 = a11 (b12 − b22)             M7 = (a12 − a22)(b21 + b22)
M4 = a22 (b21 − b11)

c11 = M1 + M4 − M5 + M7     c12 = M3 + M5
c21 = M2 + M4               c22 = M1 − M2 + M3 + M6
```

(Verified numerically in this repo's tooling — the eight identities hold for arbitrary 2×2 integer matrices.) Recurrence: `T(n) = 7T(n/2) + Θ(n²)` → case 1, leaves win: Θ(n^lg 7) ≈ Θ(n^2.81). It stays below the naive Θ(n³) forever, the same way n lg n stays below n² — but like the crossover table of Chapter 3, the constants mean Strassen only pays off around n ≈ 100+ in practice.
