# 18 — 4Sum

## Problem

Find all **unique** quadruplets summing to `target`.

**Example:** `nums = [1,0,-1,0,-2,2]`, `target = 0` → `[[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]`

## Walkthrough

Sort, then nest: fix `i`, fix `j > i`, and close the quadruplet with two pointers `L`/`R` scanning each other — same mechanics as 3Sum/167 with one more layer. Duplicates are skipped *at every level* so no quadruplet is emitted twice.

**[1] sorted, i and j fixed at the two smallest**
```text
[-2, -1, 0, 0, 1, 2]
  i   j   L        R
sum=-2-1+0+2=-1 < 0 → L++
```

**[2] L moves right — sum rises**
```text
[-2, -1, 0, 0, 1, 2]
  i   j      L     R
sum=-2-1+0+2=-1 < 0 → L++ again
```

**[3] hit — collect, then skip dups**
```text
[-2, -1, 0, 0, 1, 2]
  i   j         L  R
sum=-2-1+1+2=0 ✓ collect [-2,-1,1,2] → L++, R--
```

**[4] j advances (skipping its duplicate) — second hit**
```text
[-2, -1, 0, 0, 1, 2]
  i       j   L     R
j=0 new  sum=-2+0+0+2=0 ✓ collect [-2,0,0,2]
```

**[5] i advances — last hit, then cleanup**
```text
[-2, -1, 0, 0, 1, 2]
      i   j   L  R
sum=-1+0+0+1=0 ✓ collect [-1,0,0,1]  → done, 3 quadruplets
```

Why it works: with the array sorted, sum-too-small ⇒ only L++ helps, sum-too-big ⇒ only R−− — each (i, j) pair closes in O(n−j) instead of O((n−j)²). Skipping equal values after each hit (and when advancing i/j) is what keeps the output duplicate-free. O(n³) overall; kSum in general is O(n^(k−1)).
